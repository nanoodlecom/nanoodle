Run a workflow from a script

Build a workflow in the editor, then run the saved graph in a batch job, on a schedule, or from your own app. Choose JavaScript, Python, or Rust.

Try the same graph in each language

Download greeting.json into your project directory. It joins two Text nodes into one output named Greeting. Each example runs locally and prints Hello, world!.

To run your own workflow, choose Save in the editor, then substitute its JSON filename and output name below. For graphs that call models, set NANOGPT_API_KEY in your environment. NanoGPT bills those calls to your balance.

JavaScript

Install with npm install nanoodle. Save this as run.mjs and run node run.mjs. Package on npm ↗

import { Workflow } from "nanoodle";

const workflow = await Workflow.load("greeting.json");
const result = await workflow.run();
console.log(result.get("Greeting"));

Python

Install with python -m pip install nanoodle. Save this as run.py and run python run.py. Package on PyPI ↗

from nanoodle import Workflow

workflow = Workflow.load("greeting.json")
result = workflow.run()
print(result["Greeting"])

Rust

In a Cargo binary project, run cargo add nanoodle serde_json. Save this as src/main.rs and run cargo run from the directory containing greeting.json. Package on crates.io ↗

use nanoodle::{materialize, run, Ctx};
use std::{env, error::Error, fs};

fn main() -> Result<(), Box<dyn Error>> {
    let file = fs::read_to_string("greeting.json")?;
    let graph = materialize(&serde_json::from_str(&file)?)?;
    let key = env::var("NANOGPT_API_KEY").unwrap_or_default();
    let ctx = Ctx::new("https://nano-gpt.com", &key);
    let result = run(&graph, &ctx).map_err(|failure| failure.message)?;
    println!("{}", result.outputs["Greeting"].as_str().ok_or("missing Greeting")?);
    Ok(())
}

For shell scripts, install the Rust CLI with cargo install nanoodle --locked. Run the example with nanoodle-rs run greeting.json. For a graph that calls models, pass --api-key "$NANOGPT_API_KEY".

CLI extras

Python also installs as nanoodle-py; python -m nanoodle always works. These examples use flags shared by the JavaScript and Python CLIs.

npx nanoodle run graph.json --input "Shared test brief=One red bicycle wheel on a cream background." --set n3.size=1:1 --out ./out --json
npx nanoodle run graph.json --input "Shared test brief=@brief.txt" --env-file .env
  • --env-file path — load NANOGPT_API_KEY from a .env-style file (--key wins if both are set)
  • --input k=@path — read a file (media as media; .txt / .md / .json as text)
  • --set k=v — override a setting (n3.model=…)
  • --out dir — save media outputs to disk
  • --json — machine-readable result

Inputs, outputs, settings

The JavaScript and Python packages expose the workflow's interface before you run it through wf.inputs, wf.outputs, wf.settings. Input keys are flexible (case-insensitive): the node's custom name ("Still brief", "Shared test brief"), nodeId.field ("n2.system"), or the input's label. A workflow with exactly one required input also accepts a bare value: wf.run("hello"). Settings use nodeId.field keys ("n3.model"). Named-node keys match across JS 0.8.0 and Python 0.5.0 — run inspect if a published graph used an older Python label.

Media inputs take a local file (mediaFromFile / media_from_file), a hosted URL, or raw bytes (MIME sniffed). Media is sent inline as base64 (NanoGPT has no upload endpoint); files over ~4.4 MB (~3.5 MB for transcription) are refused locally with a clear error before any paid call.

NanoGPT bills per generation. Local nodes run on your machine. Loading, validating and inspecting workflows never calls the API, and bad inputs (unknown node types, missing required inputs, missing API key) fail before anything is spent. No telemetry, no analytics; the key is never logged. Damaged share links (a character flipped in transit) are recovered best-effort and warned; only damage inside the graph itself is unrecoverable.

What runs where

For sprite stacking, connect the 3D input’s model output to Slice 3D, then connect its sheet output to Sprite stack render. The site and all three executors can render a still or an H.264 turntable locally. This graph runs without an API key or a separate FFmpeg installation.

Pure-logic nodes (text, uploads, choice, join, comment) run locally; generation nodes (llm, image, edit, inpaint, vision, video, lipsync, music, remix, tts, transcribe) call NanoGPT. The 6 media-processing nodes (resize, vframes, combine, soundtrack, trim, extractaudio) also run headlessly. They do their work on your machine and never spend. Some of them need ffmpeg and ffprobe on PATH:

ffmpeg is a soft dependency, not a package dependency. Install it with apt install ffmpeg or brew install ffmpeg. If a node needs it and it is absent, that node stops the run with a clear error that names it. The error arrives when the node's turn comes, so paid nodes earlier in the graph have already spent — run a media-only graph once to prove your setup before you wire a paid node in front of it.

The ⚖️ decide node (NanoGPT decision models) runs headless too, with the same requests and costs as the editor. Text-only decisions need nothing extra. Wired images are shrunk with ffmpeg. A yes/no gate that answers no is a result, not a failure: that node reports gated and everything behind it reports skipped (never run, never billed). The run succeeds and the CLI exits 0 with a gated list in its JSON summary.

The executors also support cleanvoice for voice isolation, model3d for 3D generation, mupload for 3D inputs, and endpoint for custom endpoints.

Only an unknown node type is refused up front: the libraries warn at load and throw at run() before any network call. That is how a graph saved before 2026-07-22 with the retired draw node behaves. The full node table is on the format page.

Same graphs, other doors

Need the graph as an agent tool, a CI step, or a one-task skill? Same noodle-graph.json, different wrapper:

  • nanoodle-mcp — saved graphs become typed MCP tools
  • run-noodle-action — run a graph in GitHub Actions
  • noodle-skills — prebuilt one-task agent skills, no graph editing

A saved workflow plus a short SKILL.md is also a skill any coding agent can run. Recipe and a poster-generator example ship in both executor repos: docs/agent-skills.md.

No account: pay per run in Nano (x402)

The JavaScript and Python packages support --pay (or a library payment callback). Each paid call returns an HTTP 402 Nano (XNO) invoice — scan/pay from a self-custody wallet; nanoodle waits for the deposit and continues. The library never holds funds or keys.

Worked examples (QR / print invoice, wallet stub, bare chat) live in both packages: nanoodle-js/examples/x402 · nanoodle-py/examples/x402.
