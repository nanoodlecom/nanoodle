Run workflows headlessly

The URL is the package. Paste a share link from chat, a tweet, or Steal a noodle. Inspect it offline. Run it from Node or Python. Same noodle-graph.json, same NanoGPT API, your own key.

Under a minute

  1. Install nanoodle — that is the package name on both registries. The GitHub repos are nanoodle-js and nanoodle-py. Do not npm install nanoodle-js.
  2. inspect the share link. Offline. No key. Prints inputs, outputs, settings.
  3. run it. That call spends your NanoGPT balance.

Quote the URL. # starts a comment in most shells. Direct #g= / #j= / #a= links decode fully offline; only fragment-less short links touch the network (redirect headers, no credentials). App links (#a=) load the graph only — the app shell stays in the browser.

Install nanoodle. Not nanoodle-js. npm 0.8.0 and PyPI 0.5.0 are both named nanoodle. Zero runtime dependencies (Node ≥ 20 with built-in fetch; Python ≥ 3.9, stdlib only). Same graphs, same semantics. A saved noodle-graph.json works anywhere a share URL does.

CLI extras

Python also installs as nanoodle-py; python -m nanoodle always works. Flags match across both CLIs:

npx nanoodle run graph.json --input "Shared test brief=One red bicycle wheel on a cream background." --set n3.size=1:1 --out ./out --json
npx nanoodle run graph.json --input "Shared test brief=@brief.txt" --env-file .env
  • --env-file path — load NANOGPT_API_KEY from a .env-style file (--key wins if both are set)
  • --input k=@path — read a file (media as media; .txt / .md / .json as text)
  • --set k=v — override a setting (n3.model=…)
  • --out dir — save media outputs to disk
  • --json — machine-readable result

Inputs, outputs, settings

Both packages expose the workflow's interface before you run it — wf.inputs, wf.outputs, wf.settings. Input keys are flexible (case-insensitive): the node's custom name ("Still brief", "Shared test brief"), nodeId.field ("n2.system"), or the input's label. A workflow with exactly one required input also accepts a bare value: wf.run("hello"). Settings use nodeId.field keys ("n3.model"). Named-node keys match across JS 0.8.0 and Python 0.5.0 — run inspect if a published graph used an older Python label.

Media inputs take a local file (mediaFromFile / media_from_file), a hosted URL, or raw bytes (MIME sniffed). Media is sent inline as base64 (NanoGPT has no upload endpoint); files over ~4.4 MB (~3.5 MB for transcription) are refused locally with a clear error before any paid call.

Every run() spends real money from your NanoGPT balance — NanoGPT bills per generation. Loading, validating and inspecting workflows never calls the API, and bad inputs (unknown node types, missing required inputs, missing API key) fail before anything is spent. No telemetry, no analytics; the key is never logged. Damaged share links (a character flipped in transit) are recovered best-effort and warned; only damage inside the graph itself is unrecoverable.

What runs where

Pure-logic nodes (text, uploads, choice, join, comment) run locally; generation nodes (llm, image, edit, inpaint, vision, video, lipsync, music, remix, tts, transcribe) call NanoGPT. The 6 media-processing nodes (resize, vframes, combine, soundtrack, trim, extractaudio) also run headlessly. They do their work on your machine and never spend. Some of them need ffmpeg and ffprobe on PATH:

resizePure JS for a PNG source; ffmpeg for any other formatffmpeg
trimPure JS for a PCM WAV source; ffmpeg for any other formatffmpeg

ffmpeg is a soft dependency, not a package dependency. Install it with apt install ffmpeg or brew install ffmpeg. If a node needs it and it is absent, that node stops the run with a clear error that names it. The error arrives when the node's turn comes, so paid nodes earlier in the graph have already spent — run a media-only graph once to prove your setup before you wire a paid node in front of it.

Only an unknown node type is refused up front: the libraries warn at load and throw at run() before any network call. That is how a graph saved before 2026-07-22 with the retired draw node behaves. The full node table is on the format page.

Same graphs, other doors

Need the graph as an agent tool, a CI step, or a one-task skill? Same noodle-graph.json, different wrapper:

  • nanoodle-mcp — saved graphs become typed MCP tools
  • run-noodle-action — run a graph in GitHub Actions
  • noodle-skills — prebuilt one-task agent skills, no graph editing

A saved workflow plus a short SKILL.md is also a skill any coding agent can run. Recipe and a poster-generator example ship in both executor repos: docs/agent-skills.md.

No account: pay per run in Nano (x402)

Skip the API key entirely. With --pay (or a library payment callback), each paid call returns an HTTP 402 Nano (XNO) invoice — scan/pay from a self-custody wallet; nanoodle waits for the deposit and continues. The library never holds funds or keys.

Worked examples (QR / print invoice, wallet stub, bare chat) live in both packages: nanoodle-js/examples/x402 · nanoodle-py/examples/x402.
