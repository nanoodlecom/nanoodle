Draw a box, say what goes in it

A photo, two box masks and two short prompts → region-only edits that stack.

Visual review · 2026-10-08 · Reported saved run: $0.078. meta/muse-image/text-to-image · flux-lora/inpainting

Muse makes the photo. Each Box is a small mask where white marks the region to repaint. Flux Inpainting gets the photo, the box and what goes in it, and repaints only that region. Box 2 edits the result of Box 1, so the edits stack like layers. Inspired by <a href="https://x.com/Dennis84322486/status/2108195758256054436">Scumble</a>, a ComfyUI image editor by @Dennis84322486 built on the same idea.

References that went in

Muse makes a rainy neon plaza. Box 1 asks for a robot ramen vendor: Flux Inpainting paints a white robot behind a wooden cart with a glowing lantern and a bowl of food, plus a parked car and a pink-lit building inside the same box. Outside the box the plaza is unchanged. Box 2 asks for a red ramen-delivery scooter: it repaints those shopfronts and parks a small dark scooter by a door. No red, no ramen box, and the new sign is garbled.

Make it yours

  1. Open the graph — save first if the canvas already has your work. Undo brings yours back.
  2. Rewrite Scene for a different photo, then What goes in box 1 and What goes in box 2 for what each box should hold. To edit your own photo, replace First photo with an Image input. To move a box, upload a new mask (white or opaque = repaint) to Box 1 or Box 2, or unwire it and brush the area inside the Inpaint node. Running the graph makes three paid image calls.
  3. Check the editor estimate, then run with your NanoGPT key. The saved run reported $0.078: Muse $0.01 and two Flux Inpainting calls at $0.034 each. Prices and results vary.
  4. Compare the three frames. Outside each box the plaza should not change. Box 1 adds the robot vendor. Box 2 repainted the shopfronts and left a small dark scooter, not the red ramen scooter it asked for. A big box lets the model put the object anywhere inside it.
